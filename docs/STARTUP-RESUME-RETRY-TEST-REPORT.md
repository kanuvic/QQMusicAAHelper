# 继续上次播放重试与默认选项（0.1.5）

用户实车反馈：连接 AA 后未自动继续播放，需要手动按播放。慢速连接后再次暂停是用户提出的可能原因，本次没有实车日志证明具体原因。

## 行为

仅“继续上次播放”启用启动重试。首次发送播放请求后每3秒检查真实 QQ音乐状态，未处于 PLAYING 时再次发送，最多10次重试（加首次共11轮）。第10次重试在约30秒，最后再等待3秒确认，约33秒仍未播放则显示超时。确认PLAYING即结束，不能保证覆盖确认成功之后才发生的再次暂停。

主动在助手或 AA 暂停、换启动选项、撤销通知使用权都会取消重试，避免覆盖主动暂停。QQ音乐源自行暂停则不会调用助手的取消路径，可在下一次检查时重发。重复执行启动设置会取消旧任务，避免并行重试。手动PLAY本身仍只恢复当前队列，不启用此启动重试。

“跟随 Android Auto 设置”移到第一项，成为首次安装 / 无效配置的默认值；按枚举名称保存的旧选择保持有效，不强行覆盖原RESUME用户。该选项仍只准备会话，不主动开始播放，不使用本次重试。媒体会话准备的原16秒超时与刷歌、最近歌曲入口的等待策略不变。

## 验证

- 6项本地单元测试通过：3秒间隔与10次上限、成功停止、最后一轮成功、取消后拒绝旧回调、新启动取消旧任务、状态检查时权限撤销。
- 首次真机重试测试的前提失败：QQ音乐没有Session，未混入通过结果。准备真实播放队列后，单独重试通过6.196秒。
- 随后真机3项集成测试通过9.688秒：首次发送后在QQ源侧暂停，约3秒后确实重发并恢复PLAYING；助手主动暂停后不再重发；新默认为INHERIT且旧RESUME配置保留。
- 日志两次重发间隔约3.0秒（首组3.026秒、复验3.007秒）。成功确认来自真实QQ音乐，不伪造桥接播放状态。
- 真机设置界面确认INHERIT第一项、RESUME第二项，旧选择RESUME仍勾选。手机覆盖安装0.1.5 Debug，测试结束暂停，未修改用户保存的选择或亮屏设置。
- Debug / Release构建与lint通过，发行签名沿用原密钥。10次全部无效及最后一次成功的边界通过虚拟时间测试，未在真实手机制造30秒持续故障。新版未在用户汽车上或DHU连接场景验证；仍需实车复验。
