# 手机应用启动设置按钮验证（0.1.4）

首页新增“启动 QQ音乐并应用设置”，读取本机当前设置并复用真实 AA 连接时的 `applyStartupMode`。RESUME / INHERIT 先打开 QQ音乐界面；RADIO / RECENT 通过相应链接直接打开 QQ音乐入口。“启动 QQ音乐”仍只打开界面，PLAY 仍继续当前队列。

手机测试不能模拟 Android Auto 后续的自动播放请求。INHERIT 只准备会话，既不主动开始播放，也不强制暂停已在播放的音乐；按钮会提示这一行为。

## 真机按钮验证

三星手机，QQ音乐 20.9.0.8，通知使用权已授权；逐项在设置界面选择，再实际点击新按钮。

| 选项 | 结果 |
| --- | --- |
| 继续上次播放 | 日志 RESUME，发出 play，真实 QQ音乐 PLAYING |
| 播放刷歌 | 日志 RADIO，3.4 秒后确认真实 PLAYING，歌曲“雀跃” |
| 播放最近歌曲 | 日志 RECENT，已提交入口请求；16 秒后超时，真实源仍 PAUSED。本次未确认成功播放 |
| 跟随 Android Auto 设置 | 日志 INHERIT，原 PAUSED 状态保持；未发起 play，符合手机预览语义 |

测试结束暂停，设置恢复原 RESUME，临时保持亮屏设置恢复原值 0。未卸载手机上的 Debug 版本，已覆盖更新至 0.1.4 Debug。

重复应用设置会取消上一轮入口等待与恢复重试，避免旧请求影响新选择；已有 Session 时清除旧入口超时状态。Debug / Release 构建与 lint 通过。发行 APK 沿用发行密钥签名、不可调试。新按钮不等同于 AA / DHU 或真实汽车测试，不保证 QQ音乐的最近歌曲入口每次自动播放成功。
