# 无助手时 QQ音乐启动顺序对照

日期：2026-10-09。Samsung S24，官方 DHU，经 ADB 隧道连接。助手及测试包均已卸载；QQ 原数据保留，没有清空歌曲历史。

两种场景都不主动按播放。每次开始前退出 DHU、强停 QQ，并确认 QQ 进程和媒体会话消失。强停是用于建立无会话前提，不等同于普通后台回收。

## 场景一：先只打开 QQ，再连接 AA

确认手机解锁，打开 QQmusic 的真实 launcher。手机主页已经出现，上次歌曲“痴心绝对 / 李圣杰”的底部播放器按钮为“播放”，没有点击。

连接前 QQ 已创建 QQMusicMediaSession，active=true，状态 NONE(0)，有歌名与歌手，queue size=0。

启动 DHU 并等待 AA 连接后，QQ 仍为 NONE(0)。DHU 仪表盘显示地图和“为您推荐”占位，没有 QQ 歌曲卡片。重复查看结果相同。

因此，仅启动 QQ / 仅存在 MediaSession / 有元数据，都不足以保证 AA 将其呈现为歌曲卡片。

## 场景二：先连接 AA，再只打开 QQ

准备时确认 QQ 已强停、进程和媒体会话消失。DHU 已连接，仅“为您推荐”占位。手机自动锁屏，用户再次解锁后，保持 AA 连接，只通过真实 launcher 打开 QQ，没有发送播放按键、播放 URL 或媒体控制命令。

QQ 启动后再次创建 MediaSession，状态 NONE(0)，有上次“痴心绝对 / 李圣杰”的元数据。活动记录确认 QQ AppStarterActivity 已打开。手机 UI 自动化等待空闲因界面持续变化失败，没有根据陈旧控件执行点击；启动与不播放通过真实会话及活动状态核对。

DHU 未出现 QQ 歌曲卡片。推荐卡片从占位变为“无任何推荐内容”，仍只有一个轮播位置。

## 对照结论

| 顺序（均不点击播放） | QQ 媒体会话 | DHU QQ 播放卡片 |
| --- | --- | --- |
| 只打开 QQ，然后连接 AA | 有，active=true、NONE(0)，带上次歌曲信息 | 没有 |
| QQ 已关闭时连接 AA，再只打开 QQ | 有，NONE(0)，带上次歌曲信息 | 没有 |

此前在同一测试环境中，QQ 实际播放后卡片出现，随后暂停时仍能显示。当前对照说明：仅有会话、仅有元数据和曾进入真实播放状态不能混为一谈；不能笼统地说“有 QQ session 就一定显示卡片”。

如希望连接后自动进入可用歌曲卡片，助手的“继续上次播放”会主动请求播放；只拉起应用 / 只准备会话不能据此保证卡片出现。这里没有修改启动模式，也没有为了验证卡片而额外点击播放。

结论限本机 QQ / AA / DHU 和保留上次歌曲的数据状态；没有清空 QQ 账号、数据，也没有测试全新安装。强停前提不等同于正常后台进程回收。这两次最终都保持不播放，助手仍卸载，DHU 保留连接供用户查看。
